# Design System — 토큰과 규칙

디자인 시스템은 "값의 출처"다. 컴포넌트가 색·간격·글꼴을 직접 들고 있으면 화면마다 조금씩 달라지고, 고칠 때 전부 찾아다녀야 한다. 토큰 한 곳에서 정하고 모든 컴포넌트가 그것만 쓰게 한다.

## 0. 시작: 시스템이 있는가

1. 사용자가 디자인 시스템(Figma, 토큰 파일, 스타일 가이드, 기존 CSS 변수)을 제공했는지 확인한다. `frontend/src/style.css`의 `:root` 변수, `tokens.*`, `design/` 폴더를 찾는다
2. **있으면** 그 토큰과 컴포넌트 규칙을 읽고 요약 표를 만든 뒤 그대로 쓴다. 새 토큰을 추가할 때는 기존 명명 규칙을 따른다
3. **없으면** 아래 2절의 기본 토큰 세트를 제안서로 작성해 리더를 통해 사용자 확인을 받는다. 확인 전에 화면에 적용하지 않는다. 레퍼런스(ChatGPT 데스크톱)의 인상을 토큰으로 옮기되 색상값은 "제안"으로 표시한다

## 1. 토큰 구조 (CSS 변수, `style.css`의 `:root`)

| 범주 | 토큰 예 | 규칙 |
|------|--------|------|
| 색 | `--color-bg`, `--color-surface`, `--color-text`, `--color-text-muted`, `--color-border`, `--color-accent`, `--color-danger` | 의미 이름만. `--gray-200` 같은 값 이름은 토큰 뒤에 숨긴다 |
| 메시지 | `--color-bg-user`, `--color-bg-assistant` | 사용자·AI 구분은 배경 또는 정렬로. 둘 다 쓰지 않는다 |
| 글꼴 | `--font-sans`, `--font-mono`, `--text-sm/base/lg`, `--leading` | 본문 16px 기준, 줄 간격 1.6 |
| 간격 | `--space-1 … --space-8` (4px 배수) | 여백은 이 단계만 쓴다 |
| 반경·그림자 | `--radius-sm/md/lg`, `--shadow-sm` | 그림자는 떠 있는 요소(Drawer, 메뉴)에만 |
| 레이아웃 | `--sidebar-w`, `--content-max-w`, `--input-h` | 채팅 본문 최대 폭 720~800px |
| 전환 | `--ease`, `--dur-fast/base` | 150ms·250ms. 그 이상은 쓰지 않는다 |

다크 모드는 `[data-theme="dark"]` 또는 `prefers-color-scheme`로 같은 토큰 이름의 값만 바꾼다. 컴포넌트는 모른다.

## 2. 기본 토큰 제안 (시스템이 없을 때)

제안서 형식: 위 표의 토큰마다 값·근거 한 줄. 색은 명도 대비 4.5:1(본문)·3:1(보조)을 만족하는 값만. 레퍼런스에서 가져온 인상(넓은 여백, 거의 없는 테두리, 중립 회색 축, 강조색 한 가지)을 근거로 적는다. 사용자가 바꾼 값을 그대로 반영한다.

## 3. 적용 규칙

- 컴포넌트 CSS에 원시 값(`#fff`, `12px`, `0.2s`) 금지. 토큰만. 예외는 `0`, `1px`(테두리), `100%`
- 새 컴포넌트를 만들기 전에 기존 클래스·컴포넌트를 찾는다. 같은 모양이 두 곳이면 공통으로 뽑고, 한 곳이면 뽑지 않는다
- 상태(hover/focus/active/disabled)는 토큰 조합으로 표현하고 모든 상호작용 요소에 같은 패턴을 쓴다. focus는 `:focus-visible` 윤곽선 필수
- 토큰을 추가·변경하면 `_workspace/02_designer_progress.md`의 "토큰 변경" 표에 이름·값·이유를 적는다

## 4. 끝내기 전 확인

- `grep -nE '#[0-9a-f]{3,6}|[0-9]+px' frontend/src/*.css frontend/src/*.tsx`로 토큰 밖 원시 값이 남았는지 본다 (허용 예외 제외)
- 라이트·다크 두 모드에서 대비 기준 통과
- 프론트 검사와 빌드 통과
