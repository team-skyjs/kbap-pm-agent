# Chat UI Design — 대화에 집중하는 화면

레퍼런스는 ChatGPT 데스크톱 앱이다. 그 앱이 잘하는 것은 "화면에 대화 말고는 거의 없다"는 점이다. 이 스킬은 그 구조를 K-Bap PM Agent의 요구(제안 카드, 도구 진행 표시, 설정)에 맞게 옮긴다.

## 0. 시작

1. `design-system` 스킬로 토큰 상태를 확인한다. 토큰이 없으면 먼저 세운다
2. `specs/<feature>/spec.md`의 수용 시나리오와 `_workspace/01_cto_api-contract.md`에서 화면이 다루는 데이터(대화, 메시지, 진행 이벤트, 제안, 설정)를 확인한다. 데이터 모양은 바꾸지 않는다
3. 기존 화면(`App.tsx`, `Chat.tsx`, `ConversationList.tsx`, `ProposalCard.tsx`, `SettingsPage.tsx`)을 읽고 무엇이 이미 있는지 목록으로 만든다

## 1. 레이아웃 뼈대

```
┌───────────────┬──────────────────────────────────────┐
│ 사이드 패널    │  (헤더 최소: 대화 제목, 모델/상태 배지)   │
│  + 새 대화     │                                      │
│  대화 목록     │        중앙 채팅 영역 (max-w 중앙 정렬)  │
│  (검색/그룹)   │        메시지 … 스크롤                  │
│  설정 링크     │                                      │
│ [접기]        │  ┌────────────────────────────────┐  │
│               │  │ 입력창 (하단 고정, 자동 높이)      │  │
└───────────────┴──┴────────────────────────────────┴──┘
```

- 데스크톱: 사이드 패널 고정 폭(`--sidebar-w`), 접으면 아이콘 바 또는 완전 숨김 + 펼치기 버튼. 상태는 `localStorage`에 기억
- 모바일(≤768px): 사이드 패널은 Drawer. 상단 메뉴 버튼으로 열고, 배경 탭·ESC로 닫는다. 열려 있는 동안 본문 스크롤 잠금
- 입력창은 화면 하단 고정, 본문은 그 위에서만 스크롤. 새 메시지가 오면 사용자가 맨 아래를 보고 있을 때만 자동 스크롤

## 2. 메시지

- 사용자 메시지와 AI 메시지는 **한 가지 방식**으로 구분한다. 권장: 사용자는 오른쪽 정렬된 연한 배경 블록, AI는 왼쪽 정렬·배경 없음·아바타 없음. 말풍선 꼬리·그림자 없음
- AI 본문은 마크다운 렌더링(기존 react-markdown 유지). 제목·목록·표·인용·코드 블록에 토큰 기반 스타일. 코드 블록은 `--font-mono`, 가로 스크롤, 복사 버튼
- 제안 카드는 AI 메시지 아래 같은 폭으로. 근거·제안·실행 단계·측정 방법 네 영역은 접을 수 있는 구역으로, 채택·보류는 카드 하단 오른쪽
- 도구 진행(tool_call/tool_result)은 본문 위에 한 줄짜리 접힌 상태 행("택사노미 조회 중…" → 완료 시 체크)으로. 펼치면 요약. 대화를 가리지 않는다

## 3. 스트리밍·로딩·오류 상태

| 상태 | 표현 |
|------|------|
| 전송 직후 | 사용자 메시지 즉시 표시, 입력창 비활성, AI 자리에 점 세 개 애니메이션 |
| 진행 중 | 도구 행이 하나씩 추가. 본문 텍스트가 오면 커서 깜빡임과 함께 이어 붙임 |
| 완료 | 커서 제거, 제안 카드 표시, 입력창 활성 |
| 부분 완료(상한) | 본문 첫 줄의 사유 문장을 연한 안내 블록으로 |
| 오류 | 메시지 자리에 짧은 오류 문구 + "다시 시도" 버튼. 입력값 보존 |
| 세션 만료 | 상단 배너 "다시 로그인" + 입력값 보존 |

애니메이션은 150~250ms, 투명도·위치만. 레이아웃이 튀지 않게 높이를 예약한다.

## 4. 사이드 패널

- "새 대화" 버튼 최상단. 목록은 최근순, 제목 한 줄 말줄임, 현재 대화 강조
- 항목 hover 시 이름 바꾸기·삭제가 보이는 패턴은 계약에 해당 API가 있을 때만. 없으면 넣지 않는다(API 요청은 frontend-dev를 통해)
- 설정은 패널 하단 고정 링크

## 5. 인터랙션 상태

모든 버튼·링크·목록 항목에 hover/focus-visible/active/disabled 네 상태를 같은 토큰 조합으로. 키보드만으로 새 대화 → 입력 → 전송 → 제안 채택까지 가능해야 한다. Enter 전송, Shift+Enter 줄바꿈, ESC로 Drawer 닫기.

## 6. 설계 문서 형식 (`_workspace/04_designer_<화면>.md`)

```
# <화면> 설계
## 레이아웃 (ASCII 또는 설명)
## 컴포넌트 목록 (기존 재사용 / 신규, 이유)
## 상태표 (위 3절 형식)
## 토큰 사용 (새로 필요한 토큰)
## 반응형 분기점과 동작
## 접근성 체크 (포커스 순서, 라벨, 대비)
## 레퍼런스와 다른 점과 이유
```

구현까지 하는 작업이면 설계 문서는 짧게 쓰고 바로 구현한다. 끝나면 `ui-review` 스킬로 자기 점검 후 QA에 알린다.
