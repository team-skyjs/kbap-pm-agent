# UI Review — 보이는 것의 검증

integration-qa가 "데이터가 맞는가"를 본다면 이 스킬은 "사람이 쓰기 좋은가"를 본다. 기준은 취향이 아니라 아래 표다. 표에 없는 지적은 "제안"으로 구분해 적는다.

## 0. 준비

- 대상 화면을 데스크톱(≥1024px)·태블릿(768px)·모바일(375px) 세 폭, 라이트·다크 두 모드에서 띄운다
- 시각 항목(레이아웃·여백·구분·넘침)은 스크린샷으로 본다. 동작·접근성 항목(키보드 흐름, ESC, 포커스 가두기, 사이드바 상태 유지, hover/active, 모바일 키보드 위 입력창)은 스크린샷으로 판정하지 않는다. Playwright 스크립트(`frontend/checks/ui/`, `npm run check:ui`)로 뷰포트·다크 모드·`prefers-reduced-motion`을 에뮬레이션해 실제로 조작하고, 명도 대비·aria는 axe-core로 잰다. 스크립트가 없으면 수동 조작으로 대신하고 결함에 재현 절차를 적는다
- `_workspace/04_designer_*.md` 설계 문서가 있으면 기준으로 삼는다

## 1. 체크리스트

### 디자인 시스템 준수
- [ ] CSS·TSX에 토큰 밖 원시 값(색상 hex, px 간격, 시간) 없음 (허용 예외: 0, 1px, 100%)
- [ ] 같은 역할의 요소(버튼, 입력, 목록 항목)가 같은 토큰 조합을 씀
- [ ] 새 컴포넌트가 기존과 중복되지 않음

### 레이아웃·시각
- [ ] 채팅 본문이 중앙 정렬되고 최대 폭 안에서 읽힘
- [ ] 사용자·AI 메시지가 한 가지 방식으로 명확히 구분됨
- [ ] 테두리·그림자·장식이 필요한 곳(떠 있는 요소)에만 있음
- [ ] 여백이 토큰 단계로 일정함. 눌리거나 붙은 곳 없음
- [ ] 마크다운(제목·목록·표·코드)과 제안 카드 네 영역이 깨지지 않음
- [ ] 긴 제목·긴 코드·긴 표에서 가로 넘침 없음(말줄임 또는 스크롤)

### 상태
- [ ] 전송 직후·진행 중·완료·부분 완료·오류·세션 만료 상태가 모두 보이고 레이아웃이 튀지 않음
- [ ] hover/focus-visible/active/disabled 네 상태가 모든 상호작용 요소에 있음
- [ ] 입력값이 오류·만료 시 보존됨

### 반응형
- [ ] 768px 이하에서 사이드 패널이 Drawer로 바뀌고 열기·닫기(버튼·배경·ESC)가 됨
- [ ] 375px에서 가로 스크롤 없음, 입력창이 키보드 위에 보임
- [ ] 사이드 패널 접기 상태가 새로고침 후 유지됨

### 접근성
- [ ] 키보드만으로 새 대화 → 입력 → 전송 → 제안 채택 가능. 포커스 순서가 시각 순서와 같음
- [ ] 포커스 윤곽선이 모든 요소에서 보임
- [ ] 명도 대비 4.5:1 이상 (본문·보조 텍스트 모두, 라이트·다크 모두). 3:1은 큰 글자(18pt 이상 또는 14pt 굵게)에만 허용
- [ ] 아이콘 버튼에 라벨(aria-label), 진행 상태에 live region, Drawer에 역할·포커스 가두기
- [ ] 애니메이션이 `prefers-reduced-motion`을 존중

## 2. 결함 형식 (`_workspace/03_qa_findings.md`에 `UI-N`으로 누적)

```
### UI-N: {한 줄}
- 화면·폭·모드: {Chat / 375px / dark}
- 항목: {체크리스트 항목}
- 현상: {무엇이 보이는가, 스크린샷 경로 또는 재현 스크립트·절차}
- 기준: {토큰·설계 문서·레퍼런스 중 무엇에 어긋나는가}
- 수정 방향: {어느 파일을 어떻게}
- 심각도: 차단(기능 못 씀·접근성 실패) | 높음(일관성 깨짐) | 낮음(다듬기)
- 제안 여부: {기준표 밖이면 "제안"}
```

## 3. 판정

- 차단 0건이고 높음 0건이면 통과. 낮음은 목록으로 남기고 통과
- 자기 점검(designer)과 QA 점검이 다르면 QA 결과가 우선. 취향 차이는 "제안"으로 적고 리더가 정한다
