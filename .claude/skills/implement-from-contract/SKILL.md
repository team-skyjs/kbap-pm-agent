# Implement From Contract — 계약서대로 만들고 넘기기

계약서는 두 사람이 따로 쓴 코드가 처음 만나는 지점이다. 이 절차는 그 만남에서 깨지는 것을 줄이기 위한 것이다.

## 1. 시작: 세 파일을 읽는다

`_workspace/01_cto_tech-decisions.md`, `_workspace/01_cto_api-contract.md`, `_workspace/01_cto_task-split.md`.
`specs/<feature>/tasks.md`가 있으면 그것이 작업 목록이다. 자기 역할 태그([BE] 또는 [FE])의 태스크를 순서대로 처리하고 끝낸 태스크는 `- [x]`로 체크한다. `.specify/memory/constitution.md`의 원칙 I~V를 따른다.
자기 파트의 progress 파일(`_workspace/02_{frontend|backend}_progress.md`)이 있으면 읽고 이어서 한다.

## 2. 모듈 하나씩, 순서대로

작업 분할의 순서를 따른다. 첫 모듈은 항상 "뜬다 + 헬스체크 왕복". 큰 기능을 먼저 만들고 싶어도 참는다. QA가 경계면을 가장 빨리 확인할 수 있는 지점이기 때문이다.

모듈 하나의 절차:
1. 계약서에서 이 모듈의 엔드포인트를 찾아 **JSON 예시를 코드로 그대로 옮긴다**. 백엔드는 응답 생성부, 프론트는 타입과 파서. 필드명·중첩·감싸기 구조를 바꾸지 않는다
2. 외부 의존(LLM, Amplitude, GitHub, 반대편 파트)은 먼저 가짜로 막는다. 가짜는 계약서 예시 값을 그대로 돌려준다
3. 작동하는 가장 짧은 코드로 구현한다. 추상화·설정·"나중을 위한" 코드는 넣지 않는다. 의도적 단순화는 `ponytail:` 주석으로 표시한다
4. 실행 가능한 검사 하나를 남긴다. 프레임워크 없이 `assert` 스크립트면 된다. 최소한 "계약서 예시 JSON이 이 코드의 타입/파서를 통과하는가"
5. progress 파일을 갱신하고 QA에 알린다 (아래 형식)

커밋은 리더가 지정한 작업 브랜치에만 한다. main에 직접 커밋하지 않는다. 브랜치가 지정되지 않았으면 리더에게 묻는다.

## 3. 계약서가 틀렸거나 부족할 때

혼자 바꾸지 않는다. 반대편이 모른다. CTO에게 SendMessage:
```
[계약 변경 요청] {엔드포인트}
- 문제: {무엇이 구현 불가/부족한가}
- 제안: {바꾸고 싶은 형태, JSON 예시}
- 영향: {반대편 파트가 바꿔야 하는 것}
```
답을 기다리는 동안 의존 없는 다른 모듈을 진행한다.

## 4. 모듈 완료 보고 (QA에 SendMessage)

```
[모듈 완료] {backend|frontend} / {모듈 이름}
- 엔드포인트: {구현 또는 호출하는 목록}
- 실행: {명령 한 줄, 포트}
- 연동 상태: {LLM: mock | Amplitude: mock | GitHub: 실제 ...}
- 검사: {검사 스크립트 경로와 실행 명령}
- 계약서 대비 알고 있는 차이: {없음 | 있으면 명시}
```
"알고 있는 차이"를 숨기지 않는다. QA가 찾는 것보다 먼저 말하는 게 싸다.

## 5. QA 결함 보고를 받으면

다른 작업보다 먼저 고친다. 경계면 결함은 방치하면 다음 모듈로 전파된다.
고친 뒤 QA에 "[수정됨] {결함 ID} — {무엇을 바꿨나}, {검사 재실행 결과}"를 보낸다.
같은 결함이 두 번 나오면 개별 수정 대신 원인(공용 파서 부재, 계약 모호)을 CTO에게 올린다.

## 6. mock → 실제 전환

반대편 모듈이 완료됐다는 알림을 받으면, 작업 분할의 "통합 지점"에 따라 가짜를 실제 호출로 바꾼다. 전환 후 다시 QA에 모듈 완료 보고를 보낸다. 연동 상태 필드가 바뀌었기 때문이다.

## progress 파일 형식

`_workspace/02_{frontend|backend}_progress.md`
```
| 모듈 | 상태 | 실행 | 연동 상태 | 검사 | 비고 |
|------|------|------|----------|------|------|
| 헬스체크 | 완료 | ... | - | ... | QA 통과 |
| 채팅 | 진행중 | ... | LLM mock | ... | 계약 변경 요청 중 |
```
상태: 대기 / 진행중 / 완료 / 막힘. 막힘이면 비고에 누구의 무엇을 기다리는지 쓴다.
