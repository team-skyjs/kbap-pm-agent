# PRD: 프론트 재설계 — 대화에 집중하는 2026년형 채팅 UI

작성일: 2026-10-15 · 상태: 초안 · 상위 PRD: `PRD-kbap-pm-agent.md` · 관련: `PRD-cost-and-ui.md`(마크다운·차트 항목은 이 문서로 이관)

## 1. 개요

K-Bap PM Agent의 프론트를 ChatGPT 데스크톱 앱을 레퍼런스로 전면 재설계한다. 지금 화면은 동작은 하지만 평범한 CSS에 토큰이 없고, 글자 간격이 좁아 읽기 어렵고, 답변의 마크다운이 제대로 꾸며지지 않으며, 지표를 표나 차트로 볼 수 없다. 기존 기능과 API 연동은 그대로 두고 보이는 것과 만져지는 것만 바꾼다.

## 2. 목표

- 사용자가 대화에만 집중하는 화면: 중앙 채팅, 접히는 좌측 사이드 패널, 하단 입력창, 장식 최소
- 가독성 기준 충족: 본문 16px 이상, 줄 간격 1.6 이상, 자간·단락 간격 토큰화, 명도 대비 4.5:1(라이트·다크)
- 답변 본문 마크다운(GFM 표 포함)과 코드 블록이 깔끔하게 렌더링
- 답변 안의 데이터 블록을 프론트가 선·막대 차트로 그림 (백엔드 API 변경 없음)
- 시스템 테마(라이트·다크) 자동 적용, 데스크톱 우선, 모바일에서 깨지지 않음
- 모든 화면이 ui-review 체크리스트와 Playwright 동작 검사를 통과

## 3. 사용자 스토리

각 스토리는 한 세션에 끝나는 크기다. UI 스토리는 모두 "Playwright 검사 통과 + ui-review 스크린샷 확인"을 완료 조건에 포함한다.

### US-001: 디자인 토큰 정의
**설명:** 디자이너로서 색·글꼴·간격·반경·전환 값을 한 곳(CSS 변수)에 두어 모든 컴포넌트가 같은 값을 쓰게 하고 싶다.

**완료 조건:**
- [ ] `style.css` `:root`에 토큰 정의: 색(배경·표면·본문·보조·테두리·강조·위험·사용자 메시지 배경), 글꼴(sans·mono), 크기 단계(sm/base/lg), 줄 간격, 자간, 간격 단계(4px 배수 8단계), 반경 3단계, 그림자 1단계, 레이아웃(사이드 폭·본문 최대 폭·입력창 높이), 전환(150ms·250ms)
- [ ] 다크 모드는 `prefers-color-scheme: dark`에서 같은 토큰 이름의 값만 교체
- [ ] 본문 16px, 줄 간격 1.6, 본문·보조 텍스트 대비 4.5:1 이상 (라이트·다크 각각 계산값 기록)
- [ ] 기본 토큰 제안서를 사용자에게 보여 확인받은 뒤 적용 (`design-system` 스킬)
- [ ] 타입 검사·빌드 통과

### US-002: 앱 셸 레이아웃
**설명:** 사용자로서 화면이 중앙 채팅과 좌측 대화 목록, 하단 입력창으로 단순하게 구성되어 대화에만 집중하고 싶다.

**완료 조건:**
- [ ] 좌측 사이드 패널(고정 폭 토큰), 중앙 채팅 영역(최대 폭 720~800px 중앙 정렬), 하단 고정 입력창
- [ ] 사이드 패널 접기·펼치기 버튼. 상태는 `localStorage`에 저장돼 새로고침 후 유지
- [ ] 768px 이하에서 사이드 패널은 Drawer. 메뉴 버튼으로 열고 배경 탭·ESC로 닫으며 열린 동안 본문 스크롤 잠금
- [ ] 375px에서 가로 스크롤 없음
- [ ] 헤더는 대화 제목과 상태 배지만. 테두리·그림자는 Drawer에만
- [ ] 타입 검사·빌드 통과, Playwright 검사 통과, ui-review 스크린샷 확인

### US-003: 사이드 패널 — 대화 목록
**설명:** 사용자로서 새 대화를 만들고 기존 대화를 빠르게 찾아 전환하고 싶다.

**완료 조건:**
- [ ] 최상단 "새 대화" 버튼, 목록은 최근순, 제목 한 줄 말줄임, 현재 대화 강조
- [ ] 항목에 제안 수·채택 수 표시(기존 API 응답 그대로)
- [ ] 하단 고정 설정 링크
- [ ] hover/focus-visible/active 상태가 토큰 조합으로 일관
- [ ] 키보드만으로 목록 이동과 선택 가능
- [ ] 타입 검사·빌드 통과, Playwright 검사 통과, ui-review 스크린샷 확인

### US-004: 메시지 표현과 타이포그래피
**설명:** 사용자로서 내 메시지와 AI 메시지가 한눈에 구분되고 긴 답변도 편하게 읽히길 원한다.

**완료 조건:**
- [ ] 사용자 메시지는 오른쪽 정렬된 연한 배경 블록, AI 메시지는 왼쪽 정렬·배경 없음·아바타 없음 (구분 방식은 하나만)
- [ ] 본문 글자 크기·줄 간격·자간·단락 간격이 토큰을 따르고 US-001 기준을 만족
- [ ] 긴 제목·긴 URL·긴 코드에서 가로 넘침 없음(말줄임 또는 스크롤)
- [ ] 타입 검사·빌드 통과, Playwright 검사 통과, ui-review 스크린샷 확인

### US-005: 마크다운 렌더링
**설명:** 사용자로서 답변의 제목·목록·표·인용·코드가 꾸며져 보여 구조를 바로 파악하고 싶다.

**완료 조건:**
- [ ] 기존 react-markdown에 GFM(표·취소선·작업 목록) 확장 적용
- [ ] 제목 4단계, 순서·비순서 목록, 인용, 구분선, 강조, 링크(새 탭, 안전 속성)에 토큰 기반 스타일
- [ ] 표는 가로 스크롤 가능, 머리글 행 구분
- [ ] 코드 블록은 mono 글꼴, 가로 스크롤, 복사 버튼, 언어 표시. 인라인 코드 구분
- [ ] 제안 카드의 제안·실행 단계 텍스트도 같은 렌더러로 표시
- [ ] 모델 출력의 HTML은 렌더링하지 않음(이스케이프)
- [ ] 타입 검사·빌드 통과, Playwright 검사 통과, ui-review 스크린샷 확인

### US-006: 답변 안 데이터 블록을 차트로
**설명:** 사용자로서 답변에 들어 있는 지표 수열을 선·막대 차트로 보고 추세를 바로 읽고 싶다.

**완료 조건:**
- [ ] 마크다운 펜스 ```chart 블록의 JSON(`{"type":"line"|"bar","title":"…","x":[…],"series":[{"name":"…","values":[…]}]}`)을 차트로 렌더링
- [ ] JSON이 유효하지 않거나 형식이 다르면 차트 대신 원문을 코드 블록으로 표시(깨지지 않음)
- [ ] 차트는 토큰 색을 쓰고 라이트·다크 모두 읽힘. 범례·축 라벨·값 툴팁
- [ ] 백엔드 변경 없음. 시스템 프롬프트에 "시계열 지표를 받으면 chart 블록으로 함께 적는다" 규칙 한 줄 추가(계약 변경 아님)
- [ ] 의존성은 가벼운 차트 라이브러리 하나(번들 증가 200KB 이하)
- [ ] 타입 검사·빌드 통과, Playwright 검사 통과, ui-review 스크린샷 확인

### US-007: 입력창과 전송
**설명:** 사용자로서 하단 입력창에서 Enter로 보내고 Shift+Enter로 줄을 바꾸며, 진행 중에는 보낼 수 없음을 알고 싶다.

**완료 조건:**
- [ ] 하단 고정, 내용에 따라 자동 높이(최대 6줄), Enter 전송·Shift+Enter 줄바꿈
- [ ] 실행 중 비활성 + 안내 문구, 오류·세션 만료 시 입력값 보존
- [ ] 포커스 윤곽선 표시, 라벨(aria)
- [ ] 타입 검사·빌드 통과, Playwright 검사 통과, ui-review 스크린샷 확인

### US-008: 스트리밍·진행·오류 상태
**설명:** 사용자로서 답변이 만들어지는 동안 무엇을 조회 중인지 보이고, 끝나거나 실패했을 때 화면이 튀지 않길 원한다.

**완료 조건:**
- [ ] 전송 직후 AI 자리에 점 애니메이션, 도구 진행은 본문 위 한 줄 접힌 행("택사노미 조회 중…" → 완료 체크), 펼치면 요약
- [ ] 본문 텍스트가 오면 커서와 함께 이어 붙임. 완료 시 커서 제거, 제안 카드 표시
- [ ] 부분 완료(상한) 사유는 연한 안내 블록, 오류는 짧은 문구 + 다시 시도, 세션 만료는 상단 배너
- [ ] 높이 예약으로 레이아웃 점프 없음. 애니메이션은 150~250ms, `prefers-reduced-motion` 존중
- [ ] 사용자가 맨 아래를 보고 있을 때만 자동 스크롤
- [ ] 타입 검사·빌드 통과, Playwright 검사 통과, ui-review 스크린샷 확인

### US-009: 제안 카드 재설계
**설명:** 사용자로서 근거·제안·실행 단계·측정 방법을 접었다 펴며 읽고 채택·보류를 바로 누르고 싶다.

**완료 조건:**
- [ ] AI 메시지 아래 같은 폭. 네 영역은 접을 수 있는 구역(기본: 제안 펼침, 나머지 접힘)
- [ ] 근거는 종류(지표·코드·택사노미)별 작은 라벨, 코드 근거는 파일·함수·줄 표시, 퍼널 단계는 기존/신규 구분
- [ ] 채택·보류·되돌리기 버튼은 카드 하단 오른쪽, 상태는 색이 아닌 라벨로도 구분
- [ ] 타입 검사·빌드 통과, Playwright 검사 통과, ui-review 스크린샷 확인

### US-010: 설정 화면 재스타일
**설명:** 사용자로서 설정 화면도 같은 토큰과 레이아웃을 써서 한 제품처럼 느끼고 싶다.

**완료 조건:**
- [ ] 저장소·택사노미·Amplitude·토큰·예산 현황 구역을 같은 간격·타이포로. 폼 요소에 토큰 적용
- [ ] 상태(연결됨·미연결·마지막 동기화)는 라벨 + 색
- [ ] 기능·API 호출 변경 없음
- [ ] 타입 검사·빌드 통과, Playwright 검사 통과, ui-review 스크린샷 확인

### US-011: 접근성 기준
**설명:** 키보드만 쓰는 사용자로서 새 대화부터 제안 채택까지 끝까지 조작하고 싶다.

**완료 조건:**
- [ ] 포커스 순서가 시각 순서와 같고 윤곽선이 항상 보임
- [ ] 아이콘 버튼 aria-label, 진행 상태 live region, Drawer는 role과 포커스 가두기
- [ ] axe-core 검사에서 심각·중대 위반 0
- [ ] 타입 검사·빌드 통과, Playwright 검사 통과

### US-012: Playwright UI 검사 스크립트
**설명:** 개발자로서 위 스토리의 동작 항목을 코드로 재실행해 회귀를 잡고 싶다.

**완료 조건:**
- [ ] `frontend/checks/ui/`에 Playwright 스크립트, `npm run check:ui`
- [ ] 뷰포트 3종(1280·768·375)과 라이트·다크·reduced-motion 에뮬레이션
- [ ] 시나리오: 사이드 패널 접기 유지, Drawer 열고 닫기(ESC 포함), 키보드만으로 전송·채택, 마크다운 표·코드·chart 블록 렌더링, 스트리밍 상태 전환(백엔드 fake 모드), axe-core 통과
- [ ] 각 뷰포트·모드 스크린샷을 `_workspace/04_designer_screenshots/`에 저장 (ui-review 입력)
- [ ] 기존 검사 f1~f6과 분리, devDependency로만 추가

## 4. 기능 요구사항

- FR-1: 모든 색·글꼴·간격·반경·전환 값은 `:root` 토큰에서만 온다. 컴포넌트 CSS에 원시 값 금지(0, 1px, 100% 예외)
- FR-2: 본문 글자 16px 이상, 줄 간격 1.6 이상, 본문·보조 텍스트 명도 대비 4.5:1 이상(라이트·다크)
- FR-3: 레이아웃은 좌측 사이드 패널(접기 가능), 중앙 채팅(최대 폭 중앙 정렬), 하단 고정 입력창
- FR-4: 768px 이하에서 사이드 패널은 Drawer로 동작한다
- FR-5: 테마는 시스템 설정(`prefers-color-scheme`)을 따른다. 수동 전환 스위치는 없다
- FR-6: 답변 본문과 제안 텍스트는 GFM 마크다운으로 렌더링한다. HTML은 렌더링하지 않는다
- FR-7: ```chart 펜스 블록은 선·막대 차트로 렌더링하고, 형식 오류 시 코드 블록으로 대체 표시한다
- FR-8: 전송 직후·진행·완료·부분 완료·오류·세션 만료 여섯 상태가 화면에 구분돼 보이고 입력값이 보존된다
- FR-9: 모든 상호작용 요소는 hover/focus-visible/active/disabled 네 상태를 같은 토큰 조합으로 갖는다
- FR-10: 키보드만으로 새 대화 → 입력 → 전송 → 제안 채택이 가능하다
- FR-11: 기존 API 호출·계약 타입·SSE 처리·토큰 입력 기능은 바뀌지 않는다
- FR-12: UI 동작 항목은 Playwright 스크립트로 재실행 가능하다

## 5. 하지 않는 것

- 백엔드 API 계약 변경(근거에 시계열 필드 추가 등). 차트는 답변 본문 블록으로만
- 수동 테마 전환, 사용자별 테마 저장
- 모바일 전용 기능(제스처, 하단 탭). 모바일은 "깨지지 않음"까지
- 대화 이름 바꾸기·삭제·검색 (계약에 API 없음)
- 상태관리·UI 컴포넌트·CSS 프레임워크 추가. 차트 라이브러리 하나만 예외
- 애니메이션 장식, 그라데이션, 일러스트

## 6. 디자인 고려사항

- 레퍼런스: ChatGPT 데스크톱 앱. 넓은 여백, 거의 없는 테두리, 중립 회색 축, 강조색 하나
- 디자인 시스템이 없으므로 US-001에서 기본 토큰 제안서를 만들어 사용자 확인 후 적용
- 기존 컴포넌트(App, Chat, ConversationList, ProposalCard, SettingsPage)는 구조를 다시 짜되 데이터 흐름(api.ts)은 그대로. 표현은 frontend-designer, 데이터는 frontend-dev 소유
- 설계 문서는 `_workspace/04_designer_<화면>.md` (`chat-ui-design` 스킬 형식)

## 7. 기술 고려사항

- 스택 유지: React + Vite + TypeScript, 평범한 CSS(토큰은 CSS 변수)
- 마크다운: react-markdown + remark-gfm. 코드 하이라이트는 선택(번들 영향 보고 결정)
- 차트: 경량 라이브러리 하나(후보 비교 후 선택, 번들 200KB 이하). chart 블록 파서는 프론트에
- 시스템 프롬프트에 chart 블록 작성 규칙 한 줄 추가(백엔드 문자열 상수, 계약 변경 아님)
- 검사: Playwright + axe-core는 devDependency. CI는 기존 Pages 워크플로우에 `check:ui` 단계 추가 여부를 열린 질문으로
- 배포: GitHub Pages 그대로. 토큰 입력 기능 유지

## 8. 성공 지표

- 가독성: 본문 16px·줄 간격 1.6·대비 4.5:1을 라이트·다크 모두 만족 (계산값 기록)
- 완성도: ui-review 체크리스트 차단·높음 0건, Playwright `check:ui` 전 시나리오 통과, axe-core 심각·중대 0
- 기능 회귀 0: 기존 검사 f1~f6 통과, 질문→제안→채택→새로고침 흐름 유지
- 성능: 운영 번들 증가 300KB 이하(차트 라이브러리 포함), 첫 화면 표시 지연 체감 증가 없음
- 주관 평가: 두 사용자가 "2026년 제품처럼 세련됨"에 동의
