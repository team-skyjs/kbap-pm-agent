# PRD: Amplitude 서버 고정 인증

작성일: 2026-10-17 · 상태: 초안 · 상위 PRD: `PRD-kbap-pm-agent.md`

## 1. 요약

Amplitude 연동을 사람이 하루마다 다시 승인하지 않아도 되게 서버에 고정한다. 지금 쓰는 Amplitude MCP의 OAuth는 갱신 토큰을 주지 않아 24시간마다 끊기고, 끊긴 줄 모른 채 질문하면 Amplitude 없이 답이 만들어져 토큰 비용만 쓴다. MCP 경로로는 고정이 불가능함을 확인했고, Amplitude REST API의 프로젝트 키(만료 없음)로 바꾸면 가능하다. 그래서 기각하지 않고 경로를 바꾸는 기획으로 쓴다.

## 2. 배경

**증상 두 가지.**
1. 설정 화면에서 Amplitude를 주기적으로 "다시 연결"해야 한다.
2. 답변이 이미 나온 뒤에야 Amplitude 연결이 끊겨 있었음을 알아차린다. 비용은 이미 쓴 상태다.

**원인(2026-10-17 운영 확인).**
- 운영 DB에 저장된 Amplitude 토큰은 만료 24시간(86,399초)이고 **갱신 토큰이 비어 있다**. 우리 클라이언트는 갱신 허용(`refresh_token`)을 요청해 등록했지만 Amplitude 인증 서버가 발급하지 않는다. MCP SDK는 갱신 토큰이 없으면 만료 뒤 전체 재승인(브라우저 로그인)을 요구하고, 서버에서는 브라우저를 열 수 없어 실패한다.
- 실행 중 연결에 실패하면 런타임은 "Amplitude 없음(연결 실패)"로 표시하고 나머지 소스(코드·택사노미)만으로 답을 만든다. 이 실패는 도구 호출 기록에 남지 않아(세션을 열기 전에 실패) 사후에도 찾기 어렵다.
- Amplitude 공식 문서는 MCP 인증을 "OAuth 2.0"으로만 설명하고 토큰 수명·갱신·API 키·무인(headless) 인증을 말하지 않는다. 문제 해결 절에 "연결을 끊고 다시 승인하라"만 있다. 권한 설명에 "MCP 서비스 계정"이 나오지만 만드는 법·인증 방식은 없다.

**대안이 되는 사실.**
- Amplitude Dashboard REST API(세그멘테이션·퍼널·리텐션)와 Taxonomy API(이벤트·속성 목록, 모든 플랜)는 프로젝트 API 키 + 시크릿 키의 Basic 인증을 쓴다. 문서에 키 만료가 없다.
- 형제 레포 kbap-amplitude가 같은 K-Bap 프로젝트에서 이 방식을 운영 중이다(약 300줄 래퍼: 세그멘테이션·퍼널·리텐션·사용자 수·이벤트/속성 목록·15분 캐시). 플랜 접근 권한은 이미 증명된 셈이다.
- 운영 3일간 Amplitude 도구 호출 102건은 모두 두 도구다. `query_amplitude_data` 86건(성공 69, 실패 17 — 실패는 모두 차트 정의 오류나 프로젝트 ID 추측 오류, 인증 아님), `get_amplitude_context` 16건. 즉 에이전트가 실제로 쓰는 것은 "차트 조회"와 "이벤트·프로젝트 맥락" 둘뿐이고, REST 두 API로 덮인다.

왜 지금인가: 사이클마다 기능이 늘어 질문 빈도가 늘고 있고, 하루 한 번 재승인은 두 사람 중 누군가가 매일 해야 하는 일이 됐다. 끊긴 상태에서 나온 답은 비용뿐 아니라 "수치 없는 제안"이라는 신뢰 문제를 만든다.

## 3. 목표

**목표:** 사람이 재승인하지 않아도 Amplitude 조회가 항상 되고, 조회가 안 되는 상태라면 모델을 돌리기 전에 멈춘다.

**핵심 결과(목표 수치 없음, 기록만):**
1. 재승인 횟수 0. 설정 화면에서 "다시 연결"이 사라진다.
2. "Amplitude 없음(연결 실패)" 상태로 완료된 실행 수를 실행 기록에 남기고 조회할 수 있다. 전환 뒤 0이어야 한다.

## 4. 대상

K-Bap 개발자 2명.

- **세그먼트 A — 질문하는 개발자.** 지표가 들어간 제안을 받고 싶다. 연결 상태를 신경 쓰고 싶지 않다.
- **세그먼트 B — 운영하는 개발자.** 매일 재승인하는 사람. 서버 설정 한 번으로 끝내고 싶다.

**제약:** 사용자 2명. 공개 레포이므로 키는 서버 환경 변수와 GitHub Secrets에만 둔다. 상위 PRD의 "Amplitude는 조회 전용" 비목표를 유지한다(REST 시크릿 키는 쓰기 권한도 있으므로 코드가 조회 엔드포인트만 부른다).

## 5. 가치 제안

### 세그먼트 A — 질문하는 개발자

- **누구:** 지표 근거가 붙은 제안을 받으려는 개발자
- **왜:** 답에 수치가 있어야 결정에 쓸 수 있다
- **이전:** 연결이 끊긴 줄 모르고 질문한다. 답이 와서 보면 수치가 없고, 비용은 이미 썼다
- **방법:** 서버가 고정 키로 Amplitude를 부른다. 조회가 불가능한 상태면 실행 전에 "Amplitude 조회 불가" 안내로 멈춘다
- **이후:** 매번 수치가 들어간 답을 받거나, 비용을 쓰기 전에 문제를 안다
- **대안:** 질문 전에 설정 화면에서 연결 상태를 확인하는 습관. 우리를 택하는 이유: 사람이 확인하지 않아도 된다

**가치 제안 문장:** 개발자가 연결 상태를 신경 쓰지 않고 항상 지표가 붙은 답을 받는다.

### 세그먼트 B — 운영하는 개발자

- **누구:** Amplitude 재승인을 매일 하는 개발자
- **왜:** 반복 작업을 없애고 싶다
- **이전:** 하루 한 번 설정 화면 → 다시 연결 → 새 탭 로그인·승인
- **방법:** 서버 환경 변수에 프로젝트 API 키·시크릿 키를 한 번 넣는다
- **이후:** 재승인 작업이 사라진다. 키를 바꿀 때만 환경 변수를 고친다
- **대안:** Amplitude에 갱신 토큰 발급을 요청하고 기다리기, MCP 서비스 계정 유무 문의. 우리를 택하는 이유: 지금 되는 방법이고 형제 레포에서 검증됐다

**가치 제안 문장:** 운영자가 키 한 번 등록으로 Amplitude 연동 유지 업무를 없앤다.

## 6. 솔루션

### 6.1 흐름

1. 서버 환경 변수 `AMPLITUDE_API_KEY`·`AMPLITUDE_SECRET_KEY`(이름은 CTO 결정)를 읽는다. 둘 다 있으면 REST 경로가 켜진다.
2. 에이전트에 내부 도구 두 개를 준다. **지표 조회**(세그멘테이션·퍼널·리텐션을 한 도구의 `kind`로 받되 조회 조건은 구조화된 인자) 와 **이벤트 맥락**(Taxonomy API의 이벤트·속성 목록, 설정 화면에 올린 택사노미와 합쳐 제공). 둘 다 조회만 한다.
3. 실행 시작 전 사전 점검: 키가 없거나 가벼운 조회(이벤트 목록 1회, 결과는 캐시)가 실패하면 모델을 호출하지 않고 "Amplitude 조회 불가: <이유>"로 실행을 거절한다. 사용자가 "그래도 진행"을 고르면 Amplitude 없이 실행하되 답에 그 사실을 표시한다.
4. 설정 화면의 Amplitude 영역은 "서버 키로 연결됨 / 키 없음"만 보여 준다. "연결·다시 연결" 버튼과 OAuth 콜백 경로는 제거한다.
5. 실행 기록에 Amplitude 상태(사용·불가·사용자가 건너뜀)를 남긴다.

### 6.2 첫 버전 필수 기능

- **REST 지표 도구:** 세그멘테이션(이벤트, 기간, 지표 종류, 그룹, 필터)·퍼널(이벤트 열, 전환 창, 기간)·리텐션. 응답은 모델용 압축표로 줄인다. 날짜 범위 상한(예: 90일)과 결과 크기 상한을 둔다.
- **이벤트 맥락 도구:** Taxonomy API 이벤트·속성 목록. 15분 캐시.
- **사전 점검과 거절:** 키 없음·인증 실패·429를 구분해 실행 전에 알린다. 기존 예산 선검사와 같은 자리에서 수행한다.
- **설정 화면 정리:** OAuth 연결 UI 제거, 서버 키 상태 표시(키 값은 절대 내려주지 않는다).
- **상태 기록:** 실행별 Amplitude 상태 저장과 조회 SQL 한 줄.
- **MCP 코드 제거:** 두 런타임의 MCP 세션·OAuth 저장소·콜백 라우트를 지운다. 환경 변수로 공존시키지 않는다(경로 두 개는 유지 비용만 늘린다).

### 6.3 기술

- 새 의존성 없음(httpx 사용 중). 형제 레포 래퍼의 구조(압축표, 캐시, 날짜 가드)를 참고해 다시 쓴다. 코드 복사는 CTO 판단.
- 모델 프롬프트의 Amplitude 규칙(조회만, 범위 최소화)은 유지하고, MCP 전용 문구(`timeSeriesLimit` 등)를 새 도구 인자로 바꾼다.
- 상위 PRD의 "공식 MCP 사용" 결정은 대체된다. 이유는 ADR로 남긴다: 공식 MCP는 서버 무인 운영에 필요한 갱신 토큰을 주지 않는다.
- Dashboard REST API 제한: 동시 5요청, 5분당 비용 1,000, 시간당 108,000. 퍼널은 이벤트 수×2 비용. 사용자 2명 규모에서 여유가 크다.

### 6.4 가정과 열린 질문

- **가정:** K-Bap 프로젝트의 플랜이 Dashboard REST API를 허용한다. 형제 레포가 운영 중이므로 참이지만, 같은 키를 쓸지 새 키를 발급할지는 운영자가 정한다.
- **가정:** MCP `query_amplitude_data`가 받던 차트 정의 JSON의 표현력 중 에이전트가 실제로 쓴 범위(세그멘테이션·퍼널·리텐션)는 REST 세 엔드포인트로 덮인다. 운영 86건 호출의 인자 키 구성이 모두 차트 정의 하나였고 유형은 이 셋 안에 있었다.
- **확인됨(2026-10-17):** 커스텀 이벤트는 REST 세그멘테이션·퍼널에서 `ce:이름` 접두어로 참조한다(공식 문서). 운영 키로 이벤트 목록을 조회한 결과 K-Bap 프로젝트 이벤트 50개 중 커스텀 이벤트는 0개다. MCP 실패 기록의 "커스텀 이벤트에 신규 사용자 필터 불가"는 모델이 잘못 지정한 경우였다. 세그멘테이션의 사용자 유형 인자는 `any`·`active`만 받고 `new`는 퍼널에서만 받는다. 도구 인자 설계에 반영한다.
- **열린 질문:** Amplitude의 "MCP 서비스 계정"이 실제로 존재하고 무인 인증을 제공하는지. 조직 설정과 지원 문의로 확인한다. 존재하면 MCP 유지가 더 작은 변경이므로 이 PRD의 구현 전에 한 번 확인한다(확인 비용: 문의 1회).
- **열린 질문:** 사전 점검 실패 시 "그래도 진행" 선택지를 둘지, 아예 막을지. 첫 버전은 선택지를 두되 기본은 거절이다.
- **열린 질문:** 지금 운영 토큰의 권한이 요청한 읽기(`all:read`)와 달리 읽기+쓰기(`all:write`)로 발급되어 있다. MCP를 제거하면 사라지는 문제지만, 전환 전까지는 토큰 저장 테이블 접근을 점검한다.

## 7. 릴리스

**첫 버전:** REST 지표·이벤트 맥락 도구, 사전 점검·거절, 설정 화면 정리, 상태 기록, MCP 코드 제거, ADR.

**다음:** 사용자 활동·세션 조회 등 추가 엔드포인트가 필요해질 때. 서비스 계정이 확인되면 MCP 복귀 검토.

**하지 않는 것:** Amplitude 쓰기(차트 생성·택사노미 수정), 사람 대신 OAuth를 자동 수행하는 브라우저 자동화, 토큰 만료 알림(원인을 없애므로 불필요), 다른 분석 도구 연동.

**기간:** 백엔드 중심 한 사이클. 프론트는 설정 화면 정리와 거절 안내만.
