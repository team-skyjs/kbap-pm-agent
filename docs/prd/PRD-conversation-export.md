# PRD: 대화 전체 내보내기

작성일: 2026-10-17 · 상태: 초안 · 상위 PRD: `PRD-kbap-pm-agent.md`

## 1. 요약

에이전트와 나눈 대화 한 건을 처음부터 끝까지 PDF나 Markdown으로 저장해 팀원과 공유할 수 있게 한다. 지금은 브라우저 인쇄를 눌러도 화면에 보이는 범위만 찍힌다. 제안 카드와 채택 기록이 쌓이기 시작한 지금, 결정 근거를 채팅 창 밖으로 꺼내 공유할 길이 필요하다.

## 2. 배경

사용자가 대화 내용을 공유하려고 Chrome에서 인쇄 → PDF 저장을 시도했다. 결과물에는 스크롤 위치에 보이던 메시지 몇 개만 담겼다.

원인은 화면 구조다. 앱 껍데기가 화면 높이에 고정되어 넘치는 부분을 숨기고(`height: 100dvh; overflow: hidden`), 메시지 목록이 그 안의 스크롤 영역(`overflow-y: auto`)에 들어 있다. 인쇄는 문서 흐름을 따라 페이지를 나누는데, 스크롤 영역은 문서 흐름 밖이라 한 화면 분량만 종이에 올라간다. 인쇄용 스타일(`@media print`)은 없다.

대화 상세 API는 메시지를 통째로 돌려주고 프론트는 가상 스크롤을 쓰지 않으므로, 대화 전체가 이미 화면 DOM에 있다. 종이에 올라가지 않는 것은 레이아웃 문제일 뿐이다.

왜 지금인가: 제안 카드에 채택·보류 결정이 기록되기 시작했다. "왜 이걸 만들기로 했나"를 다른 사람에게 보여 줄 때 대화 원문이 가장 정확한 근거인데, 지금은 스크린샷을 여러 장 이어 붙이는 수밖에 없다.

## 3. 목표

**목표:** 대화 한 건을 클릭 한 번으로 전체 내용·제안 카드·차트까지 담긴 파일로 저장할 수 있다.

**핵심 결과:** 목표 수치를 두지 않는다. 내보내기 실행 건수와 형식(PDF/Markdown)만 기록해 다음 결정에 쓴다. (상위 PRD와 질문 마법사 PRD의 성공 기준 방식과 동일)

## 4. 대상

사용자는 K-Bap 개발자 2명이다.

- **세그먼트 A — 결정 근거를 팀 밖으로 공유하는 개발자.** 제안을 채택한 이유를 멘토·동료·발표 자료에 붙여야 한다. 대화 흐름(질문 → 근거 → 제안 → 결정)이 그대로 보여야 한다.
- **세그먼트 B — 대화를 문서로 다시 쓰는 개발자.** 제안 내용을 이슈·회의록·포트폴리오에 옮긴다. 복사해 붙일 수 있는 텍스트가 필요하고, 표·제목 구조가 유지돼야 한다.

**제약:** 사용자 2명, 서버 측 PDF 생성 인프라를 새로 둘 이유가 없다. 공개 레포이므로 내보낸 파일에 운영 주소가 들어가면 안 된다.

## 5. 가치 제안

### 세그먼트 A — 결정 근거를 공유하는 개발자

- **누구:** 채택한 제안의 근거를 보여 줘야 하는 개발자
- **왜:** 대화 원문이 가장 정확한 근거인데 꺼낼 방법이 없다
- **이전:** 스크롤하며 스크린샷을 여러 장 찍어 이어 붙이거나, 메시지를 하나씩 복사한다. 차트는 이미지로만 남고 제안 카드 구조가 깨진다
- **방법:** 대화 화면에 "내보내기" 버튼. PDF를 고르면 사이드바·입력창을 뺀 인쇄용 레이아웃으로 대화 전체가 페이지에 나뉘어 인쇄된다
- **이후:** 클릭 한 번으로 대화 한 건이 PDF 한 장 묶음이 된다. 제안 카드와 차트가 그대로 보인다
- **대안:** 스크린샷 이어 붙이기, 브라우저 개발자 도구로 스크롤 영역 풀기. 우리를 택하는 이유: 누구나 한 번에, 매번 같은 품질로

**가치 제안 문장:** 개발자가 결정 근거가 담긴 대화를 클릭 한 번으로 PDF로 만들어 보여 준다.

### 세그먼트 B — 대화를 문서로 옮기는 개발자

- **누구:** 제안 내용을 이슈·문서·포트폴리오에 옮기는 개발자
- **왜:** 글로 다시 쓰려면 원문 텍스트가 구조째 필요하다
- **이전:** 메시지를 하나씩 복사한다. 표와 제목은 서식이 사라지고 제안 카드는 복사 자체가 어렵다
- **방법:** "내보내기"에서 Markdown을 고르면 역할·시각·본문(원래 Markdown)·제안 카드(제목·근거·제안·실행 단계·측정 방법·채택 상태)·차트 데이터 블록이 한 파일로 받아진다
- **이후:** 파일을 열어 필요한 절만 잘라 쓴다. 표·제목·코드 블록이 그대로 산다
- **대안:** 메시지별 복사. 우리를 택하는 이유: 제안 카드까지 포함한 전체를 한 번에

**가치 제안 문장:** 개발자가 대화 전체를 구조가 살아 있는 Markdown 한 파일로 받아 바로 재사용한다.

## 6. 솔루션

### 6.1 흐름

1. 대화 화면 상단 바에 "내보내기" 버튼. 메시지가 0개인 대화에서는 비활성.
2. 누르면 PDF / Markdown 두 선택지.
3. **PDF:** 브라우저 인쇄 대화상자를 연다. 인쇄용 스타일이 사이드바·입력창·다듬기 카드·버튼을 숨기고, 앱 껍데기와 메시지 영역의 높이 고정·스크롤을 풀어 대화 전체가 문서 흐름에 놓이게 한다. 머리에 대화 제목·생성일을 붙인다. 사용자는 Chrome 대화상자에서 "PDF로 저장"을 고른다.
4. **Markdown:** 화면에 이미 있는 대화 데이터로 파일을 만들어 내려받는다. 서버 호출 없음. 파일명은 `대화제목-YYYYMMDD.md`.
5. 두 경우 모두 프론트가 내보내기 사실(대화 ID, 형식)을 기존 로그 경로로 남긴다.

### 6.2 첫 버전 필수 기능

- **인쇄용 스타일:** 화면 높이 고정과 스크롤 영역을 인쇄 매체에서만 해제. 사이드바·입력창·조작 버튼 숨김. 메시지와 제안 카드가 페이지 경계에서 잘리지 않게 끊김 방지(`break-inside: avoid`). 코드·표는 가로로 넘치지 않게 줄 바꿈.
- **차트 인쇄:** 차트 캔버스가 인쇄 폭에 맞춰 다시 그려지고, 애니메이션 없이 즉시 완성된 상태로 찍힌다. 배경색은 흰색 기준(다크 테마여도 인쇄는 밝게).
- **Markdown 내보내기:** 메시지 역할·시각·본문. 에이전트 답변은 원래 Markdown 그대로. 제안 카드는 제목 아래 근거·제안·실행 단계·측정 방법 네 절과 채택 상태(채택/보류/미정). 차트는 `chart` 코드 블록 원문 유지.
- **내보내기 버튼:** 키보드로 도달·실행 가능, 메시지 0개면 비활성.
- **운영 정보 비노출:** 내보낸 파일에 API 주소·호스트명이 들어가지 않는다(머리글은 제목·날짜만).

### 6.3 기술

- 인쇄는 브라우저 기본 기능(`window.print()` + `@media print`)만 쓴다. 서버 PDF 생성, 헤드리스 브라우저, PDF 라이브러리를 들이지 않는다. 대화 전체가 이미 DOM에 있어 레이아웃만 풀면 된다.
- Markdown은 프론트가 보유한 대화 상세 응답에서 직접 만든다. 백엔드 변경 없음.
- 기존 UI 검사(Playwright)에 인쇄 매체 에뮬레이션으로 "숨겨야 할 요소가 숨고, 메시지 영역이 스크롤 아님" 확인을 한 건 추가한다.

### 6.4 가정과 열린 질문

- **가정:** Chrome 인쇄 대화상자의 "PDF로 저장"을 사용자가 직접 고른다. 파일 자동 저장은 브라우저가 허용하지 않는다.
- **가정:** 대화 길이는 수십 메시지 수준이다. 수백 메시지 대화에서 인쇄 미리보기 지연은 측정하지 않았다.
- **열린 질문:** Markdown에 사용자 질문의 "다듬기 선택"(원문/개선안) 흔적을 넣을지. 첫 버전은 최종 전송된 메시지만 넣는다.
- **열린 질문:** 공유 링크(읽기 전용 URL)가 필요해지는 시점. 접근 제한이 머지되기 전에는 공개 레포·공개 Pages 조합에서 링크 공유가 곧 노출이므로 넣지 않는다.

## 7. 릴리스

**첫 버전:** 인쇄용 스타일 + "내보내기" 버튼(PDF/Markdown) + 내보내기 기록 + UI 검사 1건.

**다음:** 메시지 범위 선택(이 제안만 내보내기), 제안 카드만 모은 요약 내보내기, 접근 제한 머지 후 읽기 전용 공유 링크.

**하지 않는 것:** 서버 측 PDF 생성, 이미지(PNG) 내보내기, 다른 대화를 합쳐 내보내기, 외부 서비스(Notion·Slack) 직접 전송.

**기간:** 프론트만 바뀌므로 한 사이클 안에서 짧게 끝난다. 백엔드 변경 없음.
