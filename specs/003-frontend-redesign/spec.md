# Feature Specification: 프론트 재설계 — 대화에 집중하는 채팅 화면

**Feature Branch**: `feat/frontend-redesign`

**Created**: 2026-10-15

**Status**: Draft

**Input**: User description: "docs/prd/PRD-frontend-redesign.md — ChatGPT 데스크톱 앱을 레퍼런스로 프론트를 전면 재설계한다. 기능과 API 연동은 그대로 두고, 디자인 토큰, 가독성, 마크다운·표·코드 렌더링, 답변 안 데이터 블록의 차트, 시스템 테마, 반응형, 접근성, 자동 UI 검사를 갖춘다."

## User Scenarios & Testing *(mandatory)*

스토리 번호는 PRD의 US-001~US-012와 같다(US1 = US-001). 표현이 바뀌는 스토리는 모두 "자동 UI 검사 통과 + 화면 리뷰 스크린샷 확인"이 완료 조건이다.

### User Story 1 - 디자인 토큰 (Priority: P1)

디자이너가 색·글꼴·크기·줄 간격·자간·간격·반경·그림자·레이아웃 폭·전환 시간을 한 곳에 정의한다. 모든 화면은 이 값만 쓴다. 다크 테마는 같은 이름의 값만 바꾼다.

**Why this priority**: 나머지 11개 스토리가 모두 이 값을 쓴다. 가독성 기준(본문 16px, 줄 간격 1.6, 대비 4.5:1)도 여기서 정해진다.

**Independent Test**: 토큰 제안서의 계산값표(라이트·다크 대비)를 확인하고, 화면 코드에서 토큰 밖 원시 값(0·1px·100% 제외)이 검색되지 않는지 본다.

**Acceptance Scenarios**:

1. **Given** 토큰 제안서, **When** 사용자가 강조색 하나를 확인, **Then** 그 값으로 토큰이 적용된다
2. **Given** 라이트·다크 각 테마, **When** 본문·보조 텍스트 대비를 계산, **Then** 둘 다 4.5:1 이상이고 계산값이 기록돼 있다
3. **Given** 시스템이 다크 테마, **When** 화면을 연다, **Then** 같은 토큰 이름의 다크 값이 적용되고 수동 전환 스위치는 없다

---

### User Story 2 - 앱 셸 레이아웃 (Priority: P1)

사용자가 화면을 열면 좌측 대화 목록, 중앙 채팅, 하단 입력창만 보인다. 사이드 패널은 접을 수 있고, 접힌 상태가 새로고침 후에도 유지된다. 좁은 화면에서는 사이드 패널이 Drawer로 바뀐다.

**Why this priority**: 모든 화면의 뼈대다.

**Independent Test**: 1280·768·375px에서 각각 레이아웃을 확인하고, 접기 상태 유지와 Drawer 열고 닫기(배경 탭, ESC)를 조작한다.

**Acceptance Scenarios**:

1. **Given** 1280px, **When** 사이드 패널을 접고 새로고침, **Then** 접힌 상태가 유지된다
2. **Given** 768px 이하, **When** 메뉴 버튼으로 Drawer를 열고 ESC를 누름, **Then** Drawer가 닫히고 열린 동안 본문 스크롤이 잠겨 있었다
3. **Given** 375px, **When** 어떤 화면이든 연다, **Then** 가로 스크롤이 없다
4. **Given** 중앙 채팅, **When** 화면 폭이 넓다, **Then** 본문은 정해진 최대 폭(720~800px)으로 가운데 정렬된다

---

### User Story 3 - 사이드 패널 대화 목록 (Priority: P2)

사용자가 새 대화를 만들고, 최근순 목록에서 기존 대화를 찾아 전환한다. 현재 대화가 강조되고, 항목마다 제안 수와 채택 수가 보인다.

**Why this priority**: 기존 기능의 재표현이다. 셸 위에서 독립적으로 바꿀 수 있다.

**Independent Test**: 대화 3개를 만들고 키보드만으로 목록을 이동·선택하며, 현재 항목 강조와 긴 제목의 말줄임을 확인한다.

**Acceptance Scenarios**:

1. **Given** 대화 여러 개, **When** 목록을 본다, **Then** 최근순·한 줄 말줄임·현재 대화 강조·제안 수·채택 수가 보인다
2. **Given** 키보드만, **When** Tab과 Enter로 이동·선택, **Then** 대화가 전환되고 포커스 윤곽선이 보인다
3. **Given** 사이드 패널, **When** 하단을 본다, **Then** 설정 링크가 고정돼 있다

---

### User Story 4 - 메시지 표현과 타이포그래피 (Priority: P1)

사용자 메시지는 오른쪽 정렬된 연한 배경 블록, AI 메시지는 왼쪽 정렬·배경 없음이다. 긴 답변도 토큰의 글자 크기·줄 간격·단락 간격으로 편하게 읽힌다.

**Why this priority**: 제품의 핵심 화면이 읽히는지가 PRD 첫 목표다.

**Independent Test**: 긴 답변, 긴 URL, 긴 코드가 섞인 대화를 열어 가로 넘침이 없고 두 메시지가 한 방식으로만 구분되는지 본다.

**Acceptance Scenarios**:

1. **Given** 사용자·AI 메시지, **When** 화면을 본다, **Then** 정렬과 배경 하나로만 구분되고 아바타가 없다
2. **Given** 긴 URL·긴 코드, **When** 메시지에 들어 있다, **Then** 말줄임이나 블록 안 스크롤로 처리돼 화면 가로 넘침이 없다

---

### User Story 5 - 마크다운 렌더링 (Priority: P1)

사용자가 답변의 제목·목록·표·인용·코드·링크를 꾸며진 모양으로 본다. 표는 가로로 스크롤되고, 코드 블록에는 언어 표시와 복사 버튼이 있다. 제안 카드의 제안·실행 단계 텍스트도 같은 방식으로 보인다. 모델이 쓴 HTML은 화면에 해석되지 않는다.

**Why this priority**: 에이전트 답변의 구조를 읽을 수 없으면 근거를 검토할 수 없다.

**Independent Test**: 제목 4단계, 순서·비순서 목록, 작업 목록, 표, 인용, 구분선, 인라인·블록 코드, 링크, `<script>` 태그가 든 답변을 렌더링해 각 요소의 표시와 HTML 비해석을 확인한다.

**Acceptance Scenarios**:

1. **Given** GFM 표가 든 답변, **When** 표가 화면보다 넓다, **Then** 표 안에서 가로 스크롤되고 머리글 행이 구분된다
2. **Given** 코드 블록, **When** 복사 버튼을 누른다, **Then** 코드 원문이 클립보드에 들어가고 확인 표시가 잠깐 보인다
3. **Given** 링크, **When** 누른다, **Then** 새 탭으로 열리고 원래 창에 접근 권한을 넘기지 않는다
4. **Given** 답변 안 HTML 태그, **When** 렌더링, **Then** 태그가 문자 그대로 보이고 실행되지 않는다

---

### User Story 6 - 답변 안 데이터 블록을 차트로 (Priority: P2)

답변에 정해진 형식의 차트 블록이 있으면, 사용자는 그 수열을 선·막대 차트로 본다. 범례·축 라벨·값 툴팁이 있고, 형식이 틀리면 원문이 코드 블록으로 보인다. 차트 내용은 화면 낭독기 사용자에게도 표로 전달된다.

**Why this priority**: 지표 추세를 바로 읽는 가치가 크지만, 마크다운 렌더러(US5) 위에 얹힌다.

**Independent Test**: 올바른 선 차트 블록, 올바른 막대 차트 블록, 깨진 JSON 블록, 형식이 다른 JSON 블록 네 개가 든 답변을 렌더링한다.

**Acceptance Scenarios**:

1. **Given** 올바른 차트 블록, **When** 렌더링, **Then** 지정한 종류의 차트가 토큰 색으로 그려지고 라이트·다크 모두 읽힌다
2. **Given** 깨진 JSON이나 다른 형식, **When** 렌더링, **Then** 차트 대신 원문 코드 블록이 보이고 화면이 깨지지 않는다
3. **Given** 화면 낭독기, **When** 차트에 도달, **Then** 제목과 같은 데이터의 표가 읽힌다
4. **Given** 시계열 지표를 조회한 실제 질문, **When** 에이전트가 답한다, **Then** 답변에 차트 블록이 함께 들어 있다(에이전트 지시 한 줄)

---

### User Story 7 - 입력창과 전송 (Priority: P1)

사용자는 하단 입력창에서 Enter로 보내고 Shift+Enter로 줄을 바꾼다. 입력창은 최대 6줄까지 자라고, 실행 중에는 보낼 수 없다는 안내가 보인다. 오류나 세션 만료 때 쓴 내용이 남는다.

**Why this priority**: 핵심 흐름(질문)의 입구다.

**Independent Test**: 긴 입력으로 높이 증가와 6줄 상한을 확인한다. 실행 중 전송 시도, 오류 후 입력값 보존을 확인한다.

**Acceptance Scenarios**:

1. **Given** 입력창, **When** Shift+Enter를 누른다, **Then** 줄이 바뀐다. **When** Enter, **Then** 전송된다
2. **Given** 실행 중, **When** 입력창을 본다, **Then** 비활성 상태와 안내 문구가 보인다
3. **Given** 전송 후 오류나 세션 만료, **When** 화면이 돌아온다, **Then** 입력값이 그대로 남아 있다

---

### User Story 8 - 스트리밍·진행·오류 상태 (Priority: P1)

사용자는 전송 직후 대기 표시를 보고, 도구 조회가 한 줄 행으로 진행·완료되는 것을 본다. 답변이 끝나면 제안 카드가 나타난다. 부분 완료·오류·세션 만료는 각각 다른 모양으로 보이고, 화면이 튀지 않는다.

**Why this priority**: 에이전트 한 턴이 수십 초라, 진행이 보이지 않으면 멈춘 것처럼 느낀다(기존 SC-004).

**Independent Test**: 여섯 상태(전송 직후, 진행, 완료, 부분 완료, 오류, 세션 만료)를 각각 재현해 표시와 레이아웃 변화량을 확인한다.

**Acceptance Scenarios**:

1. **Given** 전송 직후, **When** 첫 진행 이벤트 전, **Then** AI 자리에 대기 표시가 보인다
2. **Given** 도구 조회 진행, **When** 조회가 끝남, **Then** 접힌 한 줄 행이 완료 표시로 바뀌고 펼치면 요약이 보인다
3. **Given** 부분 완료·오류·세션 만료, **When** 각각 발생, **Then** 안내 블록·다시 시도·상단 배너로 서로 다르게 보인다
4. **Given** 사용자가 위쪽 기록을 읽는 중, **When** 새 내용이 온다, **Then** 자동 스크롤되지 않는다
5. **Given** 동작 줄이기 설정, **When** 상태가 바뀐다, **Then** 애니메이션 없이 바뀐다

---

### User Story 9 - 제안 카드 재설계 (Priority: P2)

사용자는 근거·제안·실행 단계·측정 방법을 접었다 펴며 읽고, 카드 하단 오른쪽에서 채택·보류·되돌리기를 누른다. 상태는 색뿐 아니라 라벨로도 구분된다.

**Why this priority**: 핵심 결과(채택 건수)의 입력 지점이지만, 기존 동작을 재표현한다.

**Independent Test**: 근거 세 종류와 신규·기존 퍼널 단계가 섞인 제안 카드를 열어 구역 접기 기본값, 라벨, 버튼 위치, 상태 라벨을 확인한다.

**Acceptance Scenarios**:

1. **Given** 제안 카드, **When** 처음 보인다, **Then** 제안 구역만 펼쳐져 있고 나머지는 접혀 있다
2. **Given** 코드 근거, **When** 펼친다, **Then** 파일·함수·줄이 보인다
3. **Given** 채택, **When** 누른다, **Then** 상태 라벨이 "채택"으로 바뀌고 새로고침 후에도 유지된다

---

### User Story 10 - 설정 화면 재스타일 (Priority: P3)

사용자는 설정 화면도 같은 토큰·간격·글꼴로 보며 한 제품처럼 느낀다. 연결 상태는 라벨과 색으로 함께 보인다.

**Why this priority**: 사용 빈도가 낮다.

**Independent Test**: 설정 화면의 모든 구역과 폼 요소가 토큰 값만 쓰는지, 상태가 라벨로도 구분되는지 본다. 기존 설정 동작(저장소 등록, 택사노미 업로드, 연결, 토큰 입력)이 그대로인지도 확인한다.

**Acceptance Scenarios**:

1. **Given** 설정 화면, **When** 연다, **Then** 구역 간격·타이포가 채팅 화면과 같은 토큰을 쓴다
2. **Given** 연결 상태, **When** 미연결, **Then** 색과 함께 "미연결" 라벨이 보인다

---

### User Story 11 - 접근성 (Priority: P2)

키보드만 쓰는 사용자가 새 대화 → 입력 → 전송 → 제안 채택까지 끝까지 조작한다. 화면 낭독기는 진행 상태 변화를 읽는다.

**Why this priority**: 품질 기준이며 다른 스토리 위에서 검증된다.

**Independent Test**: 마우스 없이 전 흐름을 수행하고, 자동 접근성 검사에서 심각·중대 위반이 0인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 키보드만, **When** 전 흐름을 수행, **Then** 포커스 순서가 시각 순서와 같고 윤곽선이 항상 보인다
2. **Given** Drawer 열림, **When** Tab, **Then** 포커스가 Drawer 안에 갇힌다
3. **Given** 자동 접근성 검사, **When** 주요 화면 전부에서 실행, **Then** 심각·중대 위반이 0이다

---

### User Story 12 - 자동 UI 검사 (Priority: P1)

개발자는 위 스토리의 동작 항목을 명령 하나로 다시 돌려 회귀를 잡는다. 뷰포트 3종과 라이트·다크·동작 줄이기에서 돌고, 화면 리뷰용 스크린샷을 남긴다.

**Why this priority**: 모든 UI 스토리의 완료 조건이 이 검사에 기대므로 먼저 뼈대를 세운다.

**Independent Test**: 명령 하나로 시나리오 전체가 돌고, 뷰포트·모드별 스크린샷이 정해진 폴더에 생긴다.

**Acceptance Scenarios**:

1. **Given** 검사 명령, **When** 실행, **Then** 시나리오(사이드 패널 유지, Drawer, 키보드 전송·채택, 마크다운·차트, 스트리밍 상태, 접근성)가 뷰포트 3종 × 모드 3종에서 돈다
2. **Given** 검사 실행, **When** 끝난다, **Then** 뷰포트·모드별 스크린샷이 저장돼 있다
3. **Given** 기존 모듈 검사, **When** 실행, **Then** 새 검사와 분리돼 그대로 통과한다

---

### Edge Cases

- 차트 블록이 매우 긴 수열(수백 점)이거나 값이 비어 있을 때: 차트는 그리되 축 라벨은 겹치지 않게 줄이고, 빈 시리즈는 형식 오류로 보고 원문 코드 블록이다
- 차트 블록 안 `x` 길이와 `values` 길이가 다를 때: 형식 오류로 보고 원문 코드 블록이다
- 스트리밍 중 창 폭이 바뀌어 Drawer 전환이 일어날 때: 진행 중 표시와 입력값이 유지된다
- 테마가 화면을 연 채로 바뀔 때: 차트를 포함해 모든 색이 새 테마 값으로 바뀐다
- 아주 긴 대화(수백 메시지): 입력창과 헤더 위치가 고정되고 스크롤이 끊기지 않는다
- 저장 불가 브라우저(사생활 보호 모드): 사이드 패널 접기 상태 저장 실패가 오류를 내지 않는다
- 복사 버튼이 지원되지 않는 환경: 버튼을 숨기지 않고 실패 안내를 짧게 보인다

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 모든 색·글꼴·간격·반경·그림자·전환 값은 한 곳의 토큰 정의에서만 온다. 화면 코드에 원시 값을 쓰지 않는다(0·1px·100% 예외)
- **FR-002**: 본문 글자는 16px 이상, 줄 간격 1.6 이상이다. 본문·보조 텍스트 명도 대비는 라이트·다크 모두 4.5:1 이상이다
- **FR-003**: 레이아웃은 좌측 사이드 패널(접기 가능, 상태 유지), 중앙 채팅(최대 폭 가운데 정렬), 하단 고정 입력창이다
- **FR-004**: 768px 이하에서 사이드 패널은 Drawer로 동작한다(메뉴 버튼으로 열기, 배경·ESC로 닫기, 열린 동안 본문 스크롤 잠금, 포커스 가두기)
- **FR-005**: 테마는 시스템 설정을 따른다. 수동 전환 스위치는 없다
- **FR-006**: 답변 본문과 제안 텍스트는 GFM 마크다운(표·취소선·작업 목록 포함)으로 렌더링한다. 모델 출력의 HTML은 해석하지 않는다. 링크는 새 탭으로 열고 원래 창 접근을 막는다
- **FR-007**: 코드 블록은 고정폭 글꼴·가로 스크롤·언어 표시·복사 버튼을 갖는다
- **FR-008**: 정해진 형식의 차트 블록은 선·막대 차트로 렌더링한다. 형식이 틀리면 원문 코드 블록으로 대체한다. 차트에는 범례·축 라벨·값 툴팁과 같은 데이터의 대체 텍스트 표가 있다
- **FR-009**: 전송 직후·진행·완료·부분 완료·오류·세션 만료 여섯 상태가 화면에서 구분되고, 오류·세션 만료 후 입력값이 보존된다
- **FR-010**: 모든 상호작용 요소는 hover·focus-visible·active·disabled 네 상태를 같은 토큰 조합으로 갖는다
- **FR-011**: 키보드만으로 새 대화 → 입력 → 전송 → 제안 채택이 가능하다. 아이콘 버튼은 접근성 이름을 갖고, 진행 상태는 화면 낭독기에 알려진다
- **FR-012**: 기존 API 호출·응답 형식·스트리밍 처리·토큰 입력 기능은 바뀌지 않는다
- **FR-013**: UI 동작 항목은 명령 하나로 다시 실행되는 자동 검사로 남는다(뷰포트 3종 × 라이트·다크·동작 줄이기, 접근성 검사 포함, 스크린샷 저장)
- **FR-014**: 에이전트는 시계열 지표를 답할 때 차트 블록을 함께 쓰도록 지시받는다. 응답 형식(계약)은 바뀌지 않는다
- **FR-015**: 사용자 메시지와 AI 메시지는 정렬·배경 한 가지 방식으로만 구분된다
- **FR-016**: 애니메이션은 150~250ms 범위이고 동작 줄이기 설정을 따른다. 상태 전환에서 레이아웃이 튀지 않는다. 사용자가 맨 아래를 보고 있을 때만 자동 스크롤한다

### Key Entities

- **디자인 토큰**: 이름과 라이트·다크 값 쌍. 색·글꼴·크기·줄 간격·자간·간격·반경·그림자·레이아웃·전환
- **차트 블록**: 답변 본문 안의 데이터. 종류(선·막대), 제목, x축 라벨 목록, 시리즈 목록(이름·값 목록)
- **화면 상태**: 메시지 하나의 표시 상태(전송 직후·진행·완료·부분 완료·오류·세션 만료)
- **UI 검사 결과**: 시나리오별 통과 여부, 접근성 위반 목록, 뷰포트·모드별 스크린샷

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 본문 16px·줄 간격 1.6·대비 4.5:1을 라이트·다크 모두 만족한다(계산값 기록)
- **SC-002**: 화면 리뷰 체크리스트의 차단·높음 결함이 0건이다
- **SC-003**: 자동 UI 검사 전 시나리오가 뷰포트 3종 × 모드 3종에서 통과하고, 접근성 심각·중대 위반이 0이다
- **SC-004**: 기능 회귀가 0이다(기존 모듈 검사 통과, 질문 → 제안 → 채택 → 새로고침 흐름 유지)
- **SC-005**: 운영 번들 증가가 300KB 이하이고, 그중 차트 의존성은 200KB 이하다. 차트가 없는 화면의 첫 표시는 차트 코드를 내려받지 않는다
- **SC-006**: 두 사용자가 "2026년 제품처럼 세련됐다"에 동의한다(주관 평가)
- **SC-007**: 실제 시계열 질문 5건 중 4건 이상에서 답변에 올바른 차트 블록이 들어 있다(PRD 열린 질문 확인용, 가정)

## Assumptions

- 사용자는 기존과 같은 개발자 2명이다. 데스크톱이 주 사용 환경이고 모바일은 "깨지지 않음"까지다(PRD 5절)
- 기존 기능·API·계약 v1.1은 그대로다. 대화 이름 변경·삭제·검색은 범위 밖이다(계약에 API 없음)
- 차트 블록 형식은 PRD US-006의 JSON(`type`·`title`·`x`·`series[name, values]`)이며, 마크다운 언어 표시 `chart`인 코드 블록에 담긴다
- 강조색 하나는 토큰 제안서에서 사용자가 정한다
- 새 런타임 의존성은 마크다운 표 확장, 한국어 강조 닫힘 수정(정확성 결함, 승인된 예외), 차트 라이브러리 하나뿐이다. 상태관리·UI 컴포넌트·CSS 프레임워크는 추가하지 않는다(PRD 5절)
- 세션 만료(접근 계층의 로그인 만료)는 접근 제한 작업이 들어와야 생긴다. 그 전에는 세션 만료 표시를 시험만 준비하고 띄우지 않는다. 공유 토큰 오류는 세션 만료가 아니라 오류 상태다.
- 접근 제한 작업(별도 PR)이 일부 화면 파일과 API 모듈을 바꾼다. 재설계는 API 모듈을 건드리지 않고, 화면 파일은 접근 제한이 먼저 합쳐진 뒤 그 위에서 고친다
- 배포는 현재 방식 그대로다. 자동 UI 검사의 CI 편입은 배포 워크플로우가 접근 제한 작업으로 바뀐 뒤 따로 정한다
