# Markdown 내보내기 형식 (프론트 생성물)

API 계약이 아니다. 프론트가 대화 상세 응답(계약 `04-conversations.md`의 `GET /api/conversations/{conversationId}`)으로 만드는 파일의 형식이다. 생성 함수(`frontend/src/exportMarkdown.ts`)와 검사(`frontend/checks/check-f10.ts`)의 기준은 이 파일 하나다.

## 파일 이름

`{제목}-{YYYYMMDD}.md`

- `YYYYMMDD`: 내보낸 날짜(브라우저 로컬 시간).
- `{제목}`: 대화 `title`이다. 다음 규칙으로 다듬는다.
  1. `\ / : * ? " < > |`와 제어 문자는 `-`로 바꾼다.
  2. 연속 공백은 하나로 줄이고 앞뒤 공백·점을 지운다.
  3. 60자를 넘으면 앞 60자만 남긴다.
  4. 결과가 비었거나 `title`이 `null`이면 `대화-{id}`를 쓴다.
- 예: `스캔 퍼널 이탈 지점 개선안-20261017.md`, 제목 없음 → `대화-8-20261017.md`.

## 본문 구조

시각은 브라우저 로컬 시간 `YYYY-MM-DD HH:mm (UTC±HH:MM)`이다. 줄바꿈은 `\n`이고 파일 끝에 줄바꿈 하나를 둔다.

````markdown
# 스캔 퍼널 이탈 지점 개선안

- 대화 생성: 2026-10-15 18:12 (UTC+09:00)
- 내보낸 날짜: 2026-10-17
- 메시지: 2개

---

## 사용자 · 2026-10-15 18:12 (UTC+09:00)

스캔 퍼널에서 가장 큰 이탈 지점 찾아서 개선안 제안해줘

## 에이전트 · 2026-10-15 18:12 (UTC+09:00)

지난 30일 스캔 퍼널에서 가장 큰 이탈은 scan_start → scan_complete(성공) 구간입니다.

### 제안 1. OCR 실패 화면에 재시도·직접 입력 동선 추가 — 미정

- 유형: 개선 제안

#### 근거

- [지표] 실패한 scan_complete 중 fail_reason=ocr_empty가 62%다. — 62% (Amplitude segmentation: scan_complete(success=false) by fail_reason, 2026-09-15~2026-10-14)

#### 제안

OCR 실패 화면에 '다시 찍기'와 '메뉴 이름 직접 입력' 버튼을 둔다.

#### 실행 단계
````

## 규칙

- **머리글**: `# {title}`(없으면 `# 새 대화`). 이어서 대화 생성 시각, 내보낸 날짜, 메시지 수를 쓰고 `---`로 끝낸다. API 주소·호스트명·URL은 넣지 않는다.
- **메시지**: `createdAt` 오름차순이다. `## {사용자|에이전트} · {시각}` 다음 빈 줄, 그다음 `content`를 **원문 그대로** 둔다(표·코드·`chart` 블록 보존, 이스케이프하지 않음).
  - 실패한 에이전트 메시지(`status: "failed"`)는 본문 뒤에 `> 실패: {errorCode}`를 덧붙인다.
  - 진행 중 메시지는 내보내기가 비활성이라 나오지 않는다.
- **제안 카드**: 해당 에이전트 메시지 아래 `seq` 순서다.
  - 제목 줄: `### 제안 {seq}. {title} — {상태}`. 상태는 `adopted`→`채택`, `on_hold`→`보류`, `pending`→`미정`이다.
  - 유형 줄: `- 유형: {개선 제안|측정 설계}`(`improvement`|`funnel_design`).
  - `#### 근거`: 근거 하나에 목록 한 줄이다.
    - 지표: `- [지표] {summary} — {value} ({source})`.
    - 코드: `- [코드] {summary} — \`{file}\` · \`{function}\` · L{line}` 다음 줄에 들여쓴 펜스 코드 블록으로 snippet을 둔다. `function`이 null이면 그 조각을 뺀다.
    - 택사노미: `- [택사노미] {summary} — \`{eventName}\``.
  - `#### 제안`: `proposal` 원문이다.
  - `#### 실행 단계`: `steps`를 `1.`부터 번호 목록으로 쓴다.
  - `#### 측정 방법`:
    - 지표 줄: `- 핵심 지표: {primaryMetric}`.
    - 기준·목표 줄: `- 기준값: {baseline} · 목표: {target}`. null인 쪽은 `-`다.
    - 퍼널: `funnel`이 있으면 표 `| 순서 | 이벤트 | 구분 | 조건 | 위치 | 속성 |`다. 구분은 `기존`|`신규`, 위치는 `file · function · L{line}`(없으면 `-`), 속성은 `name(type)`을 쉼표로 잇는다. 셀 안의 `|`는 `\|`로 이스케이프한다.
  - 메모: `decision.note`가 있으면 `#### 결정 메모` 다음 원문을 둔다.
- **넣지 않는 것**: 도구 호출 목록, 사용량·비용, 다듬기 선택 흔적, API 주소.
